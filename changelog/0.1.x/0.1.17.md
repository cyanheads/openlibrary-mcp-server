# 0.1.17 — 2026-07-13

## Added

- **`.github/SECURITY.md`** — vulnerability-reporting policy (GitHub Security tab or `casey@caseyjhand.com`).
- **`.github/FUNDING.yml`** — GitHub Sponsors / Buy Me a Coffee funding links.
- **`.gitattributes`** — normalizes line endings to LF, marks binary asset extensions, and marks `bun.lock`/`CHANGELOG.md`/`docs/tree.md` `linguist-generated` so they collapse in PR diffs.

## Changed

- **`@cyanheads/mcp-ts-core`** `^0.10.9 → ^0.10.14` — re-synced skills, scripts, and `CLAUDE.md`/`AGENTS.md` docs (`ctx.state.getMany`, `ctx.enrich`, `ctx.content`, `ctx.recoveryFor`, corrected `ctx.tenantId` doc).
- **`bunfig.toml`** — `[install]` gains `minimumReleaseAge = 259200` (blocks package versions published under 3 days old, a supply-chain guard against freshly compromised releases), excluding `@cyanheads/mcp-ts-core` so framework releases are still adopted same-day; new `[install.security]` `scanner = "@socketsecurity/bun-security-scanner"` scans packages before install.
- **`Dockerfile`** — pins `oven/bun:1.3` → `oven/bun:1.3.14` in both the build and production stages; adds a BuildKit cache mount (`/root/.bun/install/cache`) to all three `bun install` steps; the build stage now installs with `--ignore-scripts` as well.
- **`package.json`** `author` — corrected to `"Casey Hand <casey@caseyjhand.com> (https://caseyjhand.com)"` (was the repo URL, not the author's site); `packageManager` `bun@1.3.11 → bun@1.3.14`.
- **`scripts/devcheck.ts` / `devcheck.config.json`** — the `outdated` check now recognizes rows held back by `bunfig.toml`'s `minimumReleaseAge` guard (bun marks them with `*`) instead of failing devcheck on an update that isn't actually installable yet; `@biomejs/biome` and `typescript` (both pinned) added to the `outdated` allowlist.

## Fixed

- **Upstream 404s leaked as raw fetch errors** — `getWork`, `getEditions`, `getAuthor`, `getAuthorWorks`, and the ISBN/OLID branch of `getEditionByIdentifier` now route through a new `fetchOrNull()` wrapper that maps an upstream HTTP 404 to `null`, reviving each caller's own `not_found` handling instead of leaking the raw `FetchHttpError`. Both of `getEditionByIdentifier`'s `notFound()` throws now carry `data.reason: 'not_found'` with contract recovery. ([#8](https://github.com/cyanheads/openlibrary-mcp-server/issues/8))
- **`openlibrary_get_edition` accepted non-numeric OCLC identifiers** — a new `oclc` branch rejects a non-numeric identifier locally (`invalid_identifier`) before the upstream call, instead of round-tripping to the bibkeys endpoint's 200 `{}` and surfacing as not-found. ([#12](https://github.com/cyanheads/openlibrary-mcp-server/issues/12))

## Security

- **`openlibrary_get_cover_url` path-traversal** — a cover/photo identifier containing `/`, `\`, `..`, or a control character was interpolated verbatim into the Covers API URL path, letting an identifier like `123/../456` resolve a different cover than the one requested. `openlibrary_get_cover_url` and the service's `getCoverUrl()` now both reject unsafe identifiers locally via a new `isUnsafeCoverIdentifier()` predicate (`invalid_identifier`), and reject `target: "author"` paired with `id_type: "isbn"` (`invalid_target`) before any URL is built. ([#9](https://github.com/cyanheads/openlibrary-mcp-server/issues/9))
