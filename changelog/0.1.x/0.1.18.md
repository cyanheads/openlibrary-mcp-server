# 0.1.18 — 2026-07-13

## Added

- **`openlibrary_get_work`** — new optional `notice` output field (enrichment block) disclosing when the text output caps a long subject list.

## Fixed

- **`openlibrary_search_books`** rendered a literal `**queryEcho:** undefined` in the text trailer for a bare query or single-filter search, on both the success and empty-result branches — both `ctx.enrich({ queryEcho })` call sites now guard on `queryEcho !== undefined`. ([#10](https://github.com/cyanheads/openlibrary-mcp-server/issues/10))
- **`openlibrary_search_books`** rendered every Internet Archive identifier per work in text output, undisclosed — `format()` now caps at 5 per work (`IA_TEXT_CAP`), with the omitted count disclosed via the enrichment trailer; `structuredContent` is unchanged, every identifier still ships there. ([#11](https://github.com/cyanheads/openlibrary-mcp-server/issues/11))
- **`openlibrary_get_work`** and **`openlibrary_search_authors`** silently truncated `subjects` / `top_subjects` in text output (caps of 10 and 5) with no disclosure — both now emit an enrichment notice naming the omitted count when a list is capped; `structuredContent` already carried the complete arrays. ([#13](https://github.com/cyanheads/openlibrary-mcp-server/issues/13))
