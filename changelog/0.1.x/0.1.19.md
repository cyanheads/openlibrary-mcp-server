# 0.1.19 — 2026-07-25

## Added

- **`openlibrary_get_edition`** — new `lc_classifications` output field carrying Library of Congress call numbers (e.g. `"TL685.7 .M366 2008"`), separated out from `lccn`.
- **`openlibrary_get_edition`** — `authors[]` entries gain a `source: 'edition' | 'work'` field marking whether the attribution came from the edition record itself or was recovered from the parent work.

## Fixed

- **`openlibrary_search_books`** failed the entire result page whenever any returned work carried `ebook_access: "unclassified"` — the output enum only listed four of Open Library's five tiers. `unclassified` is now a valid tier, and a new `toEbookAccess()` guard coalesces any future unrecognized tier to `unclassified` instead of throwing. ([#15](https://github.com/cyanheads/openlibrary-mcp-server/issues/15))
- **`openlibrary_get_edition`** returned Library of Congress *call numbers* under `lccn`, both on the ISBN/OLID route and the OCLC/LCCN route — the upstream `lccn` field was never read, only `lc_classifications`. `lccn` now maps from the real control numbers; call numbers moved to the new `lc_classifications` field. ([#16](https://github.com/cyanheads/openlibrary-mcp-server/issues/16))
- **`openlibrary_search_books`'s `language` filter was inert** — it sent `lang=`, Open Library's UI-language parameter, which filters nothing; the real filter is `language=`, and it takes 3-letter MARC codes, not the 2-letter ISO 639-1 codes the `.describe()` documented. The service now sends `language=` with a MARC code; input accepts a 2-letter ISO 639-1 code and normalizes it via a new `normalizeLanguageCode()` lookup table (`src/services/open-library/language-codes.ts`), rejecting an unrecognized 2-letter code (`unknown_language_code`) rather than silently forwarding it; `queryEcho` now reports the normalized MARC code actually sent, not the caller's raw input. Note: a caller passing a language value the previous, fully-inert filter silently accepted and ignored may now get a `ValidationError` instead — no caller could have depended on the filter itself working, but the input surface is narrower. ([#17](https://github.com/cyanheads/openlibrary-mcp-server/issues/17))
- **`openlibrary_get_edition`** returned an empty `authors` array for editions whose authorship Open Library records only on the parent work — a new fallback fetches `/works/{id}.json` and resolves its author keys when the edition's own `authors` is empty, on both the ISBN/OLID and OCLC/LCCN routes. ([#18](https://github.com/cyanheads/openlibrary-mcp-server/issues/18))

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.10.14` → `^0.10.15` — adopted the new `expectedStatuses` fetch option so a deliberate 404 (used by `fetchOrNull()` to detect absent records) logs at `debug` instead of `error`; migrated off the legacy `err.data?.statusCode` alias to the canonical `err.data?.status`.
- `@biomejs/biome` `2.5.2` → `2.5.4` (dev)
- `tsc-alias` `^1.8.17` → `^1.9.1` (dev)
