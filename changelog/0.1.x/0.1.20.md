# 0.1.20 — 2026-07-26

## Added

- **`openlibrary_search_authors`** — new `offset` output field, echoing the requested offset so an empty page still records what produced it. ([#19](https://github.com/cyanheads/openlibrary-mcp-server/issues/19))

## Fixed

- **`openlibrary_search_books`, `openlibrary_search_authors`** — an offset paged past the end of a result set that did match reported `total: 0`, misdirecting the caller's correction. Both tools now always report the upstream match count via `ctx.enrich.total()`, and the empty-page notice distinguishes a genuine zero-match query from an over-paged offset, naming the last offset that still returns a result. ([#19](https://github.com/cyanheads/openlibrary-mcp-server/issues/19))
- **`openlibrary_search_books`** — each work's `subjects` were truncated to 5 entries in `structuredContent` itself, not just in the rendered text, with no disclosure. The service now returns the complete array; the tool caps the rendered `**Subjects:**` line at 5 and discloses the omitted count via a new shared `capped-list-notice` helper (`src/mcp-server/tools/capped-list-notice.ts`), also adopted by `openlibrary_search_authors`' existing `top_subjects` disclosure. ([#20](https://github.com/cyanheads/openlibrary-mcp-server/issues/20))
- **Errors** — declared `errors[]` recovery hints never reached the client on most `ctx.fail(...)` sites — the `ctx.recoveryFor(...)` argument that puts the hint on the wire was missing. Every `not_found` throw in `openlibrary_get_work`, `openlibrary_get_author`, `openlibrary_get_editions`, `openlibrary_get_author_works`, and every `invalid_identifier` throw in `openlibrary_get_edition` now passes it. ([#21](https://github.com/cyanheads/openlibrary-mcp-server/issues/21))
- **`openlibrary_get_subject`** — the `not_found` error contract could never fire (Open Library answers any subject key with HTTP 200, echoing it back as a zero-work result), and its recovery advice told callers to retry with different casing when case is normalized before lookup — a no-op. The dead contract, its `errors[]` entry, and the service's unreachable null branch are removed; guidance now points at word-form, synonym, and broader-term alternatives instead of casing. ([#22](https://github.com/cyanheads/openlibrary-mcp-server/issues/22))

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.10.15` → `^0.10.16` — adopted three template changes: the `.gitignore` `data/` → `/data/` anchor, `--omit=dev --ignore-scripts` on the Dockerfile OTEL `bun add`, and `devcheck`'s outdated-gate change (peer-range rows no longer flagged; the release-age skip is replaced by a direct `Update === Current` comparison against the declared range).
