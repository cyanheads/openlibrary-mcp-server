# 0.2.0 — 2026-07-26

## Added

- **`openlibrary_search_inside`** — new tool searching the full-text index of Internet Archive scanned books via `search/inside.json`. Answers "which book contains this passage?", a question none of the other nine tools could. Quoted queries match an exact phrase; snippets have the upstream `{{{…}}}` highlight markers stripped. Text output caps snippets per match at 3 with the omission disclosed via enrichment; `structuredContent` carries every snippet. Brings the tool count to 10. ([#24](https://github.com/cyanheads/openlibrary-mcp-server/issues/24))

## Changed

- **BREAKING: `openlibrary_get_edition`** — `identifiers: string[]` (1–50) replaces the single `identifier` field; the output becomes `{ editions, unresolved }`. Partial success is the design: one unresolvable identifier no longer fails the rest of the batch. All four `id_type`s (ISBN, OCLC, LCCN, OLID) now route through multi-bibkey `/api/books`, which returns author names inline and removes the previous per-author secondary lookups for the ISBN/OLID path. ([#25](https://github.com/cyanheads/openlibrary-mcp-server/issues/25))
- **`openlibrary_get_edition`** — because the batch route resolves through `/api/books`, an ISBN carried by more than one duplicate catalogue record can now return a different edition record (a different OLID) than the previous route picked — both records legitimately carry that ISBN. A caller that cached an `edition_id` may see a different OLID for the same ISBN after upgrading.
- Author-enrichment requests for a batch are bounded by a new `ConcurrencyGate`, capped at `EDITION_ENRICHMENT_CONCURRENCY = 6`. The unbounded fan-out this replaces measured 90 concurrent upstream requests for a 30-identifier batch, scaling past 150 at the 50-identifier cap — a single tool call hammering Open Library's volunteer-run infrastructure. Found during review, not filed as an issue.

## Fixed

- **`openlibrary_get_cover_url`** — validates the identifier format per `id_type` × `target` before building a URL: numeric for `id`, 10 or 13 digits for `isbn`, an edition OLID (`OL…M`) for `olid`/`book`, an author OLID (`OL…A`) for `olid`/`author`. Because the Covers API answers every request with HTTP 200 and a 1×1 placeholder GIF, a malformed identifier previously produced a confident URL indistinguishable from a genuinely missing cover; it now raises `invalid_identifier` naming the expected shape. ([#23](https://github.com/cyanheads/openlibrary-mcp-server/issues/23))
