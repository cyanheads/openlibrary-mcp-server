# 0.2.1 — 2026-07-26

Framework-maintenance release — no server behavior changes. Adopts `@cyanheads/mcp-ts-core` `^0.10.16 → ^0.11.0` and the tooling it ships.

## Added

- **Native-binding strip in `scripts/clean-mcpb.ts`** — a built `.mcpb` bundle now also strips `node_modules/@duckdb/node-bindings-*/` entries, alongside the existing agent-doc strip. `mcpb pack` archives the whole project directory, so a native dependency contributes the build host's platform slice; left in, the bundle only runs on the platform it was packed on and can blow past the 25 MB registry cap. `scripts/lint-packaging.ts`'s `checkBundleEntries` fails the build if either class of entry survives. ([cyanheads/mcp-ts-core#274](https://github.com/cyanheads/mcp-ts-core/issues/274))

## Changed

- **`check-dependency-specifiers`** — now scans the `overrides` section alongside `dependencies`/`devDependencies`/`peerDependencies`/`optionalDependencies`; a floating specifier there is held to the strict (never-allowed) rule since an override exists specifically to pin a transitive off a known-vulnerable version.
- **Framework skills re-synced** — `api-canvas` (documents the new `CANVAS_TEMP_PATH` env var: DuckDB's spill-to-disk `temp_directory`, no longer implicitly sandbox-rooted), `api-config` (same), and `field-test` (`mcp_start` takes an optional startup-timeout argument for servers that build a local index at boot; `mcp_init` reports the negotiated protocol version and flags a downgrade; `mcp_call` fails loudly on transport errors instead of returning empty output; `mcp_stop` also signals the `bun run` wrapper's child process and confirms the port is free).
- **`@cyanheads/mcp-ts-core`** `^0.10.16 → ^0.11.0`.
- **`@biomejs/biome`** (dev) `2.5.4 → 2.5.5`; **`ignore`** (dev) `^7.0.5 → ^7.0.6`; **`typescript`** (dev) `^6.0.3 → ^7.0.2`; **`vitest`** (dev) `^4.1.9 → ^4.1.10`.
