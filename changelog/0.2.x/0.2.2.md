# 0.2.2 — 2026-07-26

## Fixed

- **`cover_ids`/`photo_ids` no longer carry Open Library's `-1` "empty slot" sentinel.** `open-library-service.ts` mapped `covers`/`photos` straight through at five sites; a new `sanitizeImageIds()` filters to `Number.isInteger(id) && id > 0` and is used in `getWork`, `getEditions`, `toEditionDetail`, `getAuthor`, and `getAuthorWorks`. Previously a client chaining a returned ID into `openlibrary_get_cover_url` could spend a call on a sentinel and get back a validation error. ([#26](https://github.com/cyanheads/openlibrary-mcp-server/issues/26))
- **`openlibrary_get_author_works` and `openlibrary_get_author` follow Open Library's `/type/redirect` merge stubs instead of reporting a valid author as `not_found`.** A merged author's works subresource 404s even though `/authors/{id}.json` still answers 200 with a redirect stub — the works call collapsed that ambiguity to `null`, and `getAuthor` built an empty-name result straight from the stub. Both now resolve through a shared `fetchAuthorRecord()`, bounded by `MAX_AUTHOR_REDIRECT_HOPS` (4) with cycle detection, and report the canonical `author_id` actually used. When the requested ID differs from the canonical one, both tools now set the new optional `enrichment.notice` output field (e.g. `OL2162284A is a merged record; these are the works of OL19981A. Use OL19981A for further lookups.`). ([#27](https://github.com/cyanheads/openlibrary-mcp-server/issues/27))
