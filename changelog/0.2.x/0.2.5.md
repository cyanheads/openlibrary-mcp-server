# 0.2.5 — 2026-09-19

## Added

- **`sessionMode: 'stateless'`** declared in `createApp()` — stdio, `bunx`/`npx`, and Docker now resolve one session posture instead of only the Docker image's `ENV` setting it. No tool calls `ctx.requestInput`, so nothing needs a session to answer a mid-handler prompt. `MCP_SESSION_MODE` still overrides it.
- **`MCP_SESSION_MODE` row in the README configuration table**, and an `.env.example` comment naming `auto` as the schema default and stateful as what it resolves to.
- **`bun run audit:fix`** (`bun audit fix`) — the first response to a transitive advisory, ahead of `bun update <name>`, `bun dedupe`, and `audit:refresh`.

## Changed

- **`openlibrary_search_books`'s `unknown_language_code` entry declares `thrownBy: 'service'`** (mcp-ts-core 0.13.6) — `normalizeLanguageCode` raises it below the handler, which is lint-only metadata that keeps `error-contract-unthrown` honest without moving the throw.
- **Tool error text closes with `(reason <reason> · not retryable)`** whenever `error.data` carries a `reason` or a boolean `retryable` (mcp-ts-core 0.13.5), and an argument rejection now classifies `InvalidParams` (`-32602`) carrying `data.reason: "invalid_arguments"` and a `Recovery:` line naming the offending field (0.13.2, 0.13.3).
- **A tool call whose intent is unambiguous is repaired rather than rejected** (mcp-ts-core 0.13.4) — a case-style spelling of a declared parameter (`workId`) is rewritten onto the declared key (`work_id`) before validation, and the client-injected `_meta`, `tool_call_description`, and `toolCallId` keys are ignored instead of failing the call. An unrecognized bare-word key is still rejected.
- **Upstream fetch failures no longer put the request URL on `error.data`** (mcp-ts-core 0.13.4); nothing here reads `data.url`, so no call site opts back in with `includeUrl: true`.
- **The development skill tree moved from `skills/` to `framework-skills/`** (mcp-ts-core 0.13.0) — Claude Code and Codex auto-load a plugin's root `skills/`, so this server's `.claude-plugin/` and `.codex-plugin/` were handing its development skills to every agent that installed it.
- **Bun engines floor raised to `>=1.4.0`**, matching the framework's own floor.
- **`changelog/` and `AGENTS.md` ship in the npm package**, and repo tooling re-synced from mcp-ts-core — `framework-skills/`, the `build`/`devcheck`/`lint`/`clean`/`list-skills` scripts, `changelog/template.md`, the issue forms, a `lint` key in `devcheck.config.json`, and root-anchored `.mcpbignore` patterns so a dependency's own `Dockerfile` or `biome.json` is no longer stripped from the bundle.
