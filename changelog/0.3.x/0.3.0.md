# 0.3.0 — 2026-09-24

## Changed

- **`work_id` on `openlibrary_get_work` and `openlibrary_get_editions` must match `^(?:/works/)?OL\d+W$`** ([#29](https://github.com/cyanheads/openlibrary-mcp-server/issues/29)) — an ISBN or an edition or author OLID fails `invalid_arguments` before any request, with a message routing an ISBN through `openlibrary_get_edition` (`id_type: "isbn"`). Every value the pattern rejects already failed upstream.
- **Per-endpoint-class attempt timeouts under one 50 s retry deadline** ([#32](https://github.com/cyanheads/openlibrary-mcp-server/issues/32)) — 10 s for record lookups, 30 s for searches, 45 s for `/search/inside.json`, so a call ends with a result or a classified error before a 60 s client timeout. HTTP 502/503/504, a 2xx HTML page, and a full-text timeout end the ladder without an in-loop retry; redirect hops and edition enrichment share the call's one budget.
- **`openlibrary_get_editions`, `openlibrary_get_author_works`, and `openlibrary_get_subject` echo `offset`** ([#35](https://github.com/cyanheads/openlibrary-mcp-server/issues/35)) in output and in the text header, on every path including an empty page past the end.
- **`openlibrary_search_inside` describes its latency as "usually 10–30 seconds"** in the tool description, server instructions, and README.

## Fixed

- **`openlibrary_get_edition` requests `/api/books.json`** ([#37](https://github.com/cyanheads/openlibrary-mcp-server/issues/37)) — the `/api/books` route answers 404 for every bibkey. An HTTP error status from the new batch route — a 404 included — or an HTML page now fails as `upstream_unavailable` (`ServiceUnavailable`, retryable) instead of `NotFound`; only a 429 stays `RateLimited`.
- **`openlibrary_get_edition` keeps the batch when an author lookup fails** ([#32](https://github.com/cyanheads/openlibrary-mcp-server/issues/32)) — only that edition loses its credits (or shows the author ID as the name), later lookups are skipped, and an enrichment `notice` names the failed and skipped editions.
- **`openlibrary_get_edition`'s work-level author fallback follows merge redirects** ([#42](https://github.com/cyanheads/openlibrary-mcp-server/issues/42)) on the parent work and on each credited author, returning the canonical work's credits and the canonical `author_id` and name.
- **Merged work IDs resolve to the canonical work** ([#30](https://github.com/cyanheads/openlibrary-mcp-server/issues/30)) on `openlibrary_get_work`, `openlibrary_get_editions`, and `openlibrary://works/{work_id}`, which report the canonical ID in `work_id`; the tools add a `notice` naming both IDs. A record that is not a work is `not_found`.
- **Author lookups return only `/type/author` records** ([#41](https://github.com/cyanheads/openlibrary-mcp-server/issues/41)) — a work or edition OLID passed to `openlibrary_get_author`, `openlibrary_get_author_works`, or `openlibrary://authors/{author_id}` is `not_found`, with no merge notice.
- **`include_availability` no longer fails the whole search on partial availability objects** ([#31](https://github.com/cyanheads/openlibrary-mcp-server/issues/31)) — the seven flags are optional and omitted when Open Library leaves them out, and `availability: null` reads as "no availability returned", not "no Internet Archive item".
- **An ISBN-10 ending in an `X` check digit is accepted** ([#38](https://github.com/cyanheads/openlibrary-mcp-server/issues/38)) by `openlibrary_get_edition` and `openlibrary_get_cover_url`, and sent upstream with hyphens stripped and `X` upper-cased.
- **`openlibrary_get_edition`'s `oclc` merges `oclc_numbers` and the singular `oclc_number`** ([#39](https://github.com/cyanheads/openlibrary-mcp-server/issues/39)), de-duplicated.
- **`openlibrary_search_inside` treats an HTTP 200 without a `hits.total` as `upstream_unavailable`** ([#40](https://github.com/cyanheads/openlibrary-mcp-server/issues/40)) instead of reporting zero matches; a real `hits.total: 0` still returns the no-match notice.
