# 0.3.1 — 2026-10-08

## Changed

- **`@cyanheads/mcp-ts-core` `^0.13.6` → `^0.13.14`** — tool errors end with `(request <id>)` and carry `data.requestId` (0.13.10, [mcp-ts-core#576](https://github.com/cyanheads/mcp-ts-core/issues/576)); upstream fetch errors name the URL by origin only, `https://openlibrary.org/…?…` (0.13.12, [mcp-ts-core#626](https://github.com/cyanheads/mcp-ts-core/issues/626)); a numeric string for a number, a lone string for a list, or `null` at an optional field is repaired before validation (0.13.14, [mcp-ts-core#707](https://github.com/cyanheads/mcp-ts-core/issues/707), [#602](https://github.com/cyanheads/mcp-ts-core/issues/602), [#616](https://github.com/cyanheads/mcp-ts-core/issues/616)).
- **Docker image installs production dependencies in a native-platform `deps` stage** cross-installed for each target, with OTel packages at the framework's peer ranges (0.13.10, [mcp-ts-core#575](https://github.com/cyanheads/mcp-ts-core/issues/575)) and musl-only packages pruned (0.13.11, [mcp-ts-core#608](https://github.com/cyanheads/mcp-ts-core/issues/608)). Base image Bun 1.4.0 → 1.4.2; the unread `MCP_FORCE_CONSOLE_LOGGING` variable is removed.
- **MCP Registry `server.json`**: npm entries drop the `run start:*` package arguments and use the `npx` runtime hint, and the HTTP entry sets `MCP_TRANSPORT_TYPE=http` (0.13.11, [mcp-ts-core#622](https://github.com/cyanheads/mcp-ts-core/issues/622)).
- **Explicit `ctx.recoveryFor` forwards removed** — the framework now fills each declared recovery hint (0.13.10, [mcp-ts-core#579](https://github.com/cyanheads/mcp-ts-core/issues/579)); the hints callers receive are unchanged.
- **Repo tooling**: `.env.example` documents the framework's newer variables; ignore files cover every env file, local caches, coverage output, and test fixtures; the CodeQL workflow runs one job per language; skills, scripts, and agent docs synced to 0.13.14.
