# 0.4.1 — 2026-11-15

## Added

- **Edition credits** — `openlibrary_get_edition` and `openlibrary_get_editions` return `subtitle`, `by_statement`, `contributors`, `contributions`, and `translated_from` when recorded, verbatim ([#59](https://github.com/cyanheads/openlibrary-mcp-server/issues/59)).
- **Edition `identifier`** — each `openlibrary_get_edition` row carries the input it resolved from, exactly as supplied ([#62](https://github.com/cyanheads/openlibrary-mcp-server/issues/62)).
- **Subject type** — `openlibrary_get_subject` returns `subject_type` (`place`, `person`, `time`, or `subject`), and `place: london` reads as `place:london` ([#61](https://github.com/cyanheads/openlibrary-mcp-server/issues/61)).
- **Past-end notices** — `openlibrary_get_editions`, `openlibrary_get_author_works`, and `openlibrary_get_subject` flag a page past the last result; author works make no last-offset claim, since Open Library's count can exceed the works it serves ([#60](https://github.com/cyanheads/openlibrary-mcp-server/issues/60)).

## Changed

- **Page ceilings** rise to 1000 rows on `openlibrary_search_books`, `openlibrary_search_authors`, `openlibrary_get_editions`, `openlibrary_get_author_works`, and `openlibrary_get_subject`; `openlibrary_search_inside` stays at 100. A clamp notice reports the applied limit and names a next offset only when rows exist past it, and with `OPENLIBRARY_CLAMP_LIMITS=false` every tool still advertises `maximum: 100` ([#60](https://github.com/cyanheads/openlibrary-mcp-server/issues/60)).
- **Whitespace-only criteria** on `openlibrary_search_books` and `openlibrary_search_authors` are treated as absent: beside a real criterion they are dropped, alone they fail `no_search_criteria` instead of an untyped error after four attempts. Non-blank values are still sent untrimmed ([#57](https://github.com/cyanheads/openlibrary-mcp-server/issues/57)).
- **`openlibrary_search_inside`** keeps to the full-text index's 10,000-result window: a page that would cross it is shortened with a notice, and `offset` ≥ 10000 fails `offset_past_result_window` instead of a retryable `upstream_unavailable`.
- **Non-JSON bodies** — a 2xx response that is neither JSON nor HTML reports `ServiceUnavailable` instead of a `ValidationError` with no reason, and `upstream_unavailable` on `openlibrary_get_edition`.
- **Descriptions** document the `ia:`, `author_key:`, `first_publish_year:`, and `ebook_access:` query prefixes, the route from `openlibrary_search_inside` to `openlibrary_search_books` `ia:<ia_identifier>` with a title/creator fallback, the `place:`, `person:`, and `time:` subject browse, and that Chinese is indexed under both `chi` and `cmn` ([#56](https://github.com/cyanheads/openlibrary-mcp-server/issues/56), [#61](https://github.com/cyanheads/openlibrary-mcp-server/issues/61)).
- **Framework sync** re-syncs framework skills, scripts, and the changelog template from mcp-ts-core 0.13.22.

## Fixed

- **Availability** — `include_availability` returns real work-level availability again through a keyed search lookup after the page; 0.4.0 answered `null` for every work. A work the Internet Archive answers with `null` is asked about once more after a short pause, and works still unknown are named in the notice. It costs one extra request per 100 returned works with a scan ([#55](https://github.com/cyanheads/openlibrary-mcp-server/issues/55)).
- **Language codes** — ISO 639-2/T codes (`deu`, `fra`, …) in any case map to MARC instead of matching nothing, and a 3-letter code that is neither a MARC code nor an Open Library language record (e.g. `qqq`) fails `unknown_language_code` before any request. Every MARC code, `zxx` included, is still accepted ([#56](https://github.com/cyanheads/openlibrary-mcp-server/issues/56)).
- **Search criteria** — empty or missing criteria on `openlibrary_search_books` and `openlibrary_search_authors`, `language` or `sort` alone, and a whitespace-only `openlibrary_search_inside` query fail `no_search_criteria` instead of returning a false "no matches" ([#57](https://github.com/cyanheads/openlibrary-mcp-server/issues/57)).
- **Lowercase OLIDs** — OLID-shaped IDs in any case are upper-cased before the request on `openlibrary_get_author`, `openlibrary_get_author_works`, both resources, and `openlibrary_get_cover_url` `olid`; they used to report real records as `not_found` and build placeholder cover URLs ([#58](https://github.com/cyanheads/openlibrary-mcp-server/issues/58)).
- **`openlibrary_get_edition`** fails a blank identifier as `invalid_identifier` for every `id_type`; a blank LCCN resolved an unrelated edition. The author-gap notice's retry instruction now names `id_type` `"olid"` with the listed edition IDs.
- **Notice escaping** — queries quoted inside the `openlibrary_search_authors` and `openlibrary_search_inside` notices are Markdown-escaped.
